## Executive Summary
根因定位在**成员页角色下拉**：受控 `<select value={m.role}>` 绑定的是查询缓存值，改角色走
"异步 PATCH → invalidate → 整表 refetch"，期间 `roleMutation.isPending` 把**全表所有** select 一起
`disabled`，且 PATCH 往返期间缓存值未变 → 受控 select **回弹**再刷新 —— 三者叠加就是肉眼可见的
"卡顿 + 闪"。已用**乐观更新 + 仅锁当前行**修复。另发现两处**架构级冗余**（非本次卡顿主因，但值得排期）。

## 已修复（本次）
- **[HIGH] 成员角色切换卡顿** `app/(protected)/w/[slug]/members/page.tsx` + `features/workspace/hooks.ts`
  - 问题：受控 select 无乐观值 → 回弹；`disabled={roleMutation.isPending}` 锁全表；每次改角色整表 refetch。
  - 修复：`useUpdateWorkspaceMemberRole` 加 `onMutate` 乐观写缓存 / `onError` 回滚 / `onSettled` 校准；
    select 仅锁"当前正在提交的那一行"（`variables?.memberId === m.id`）。改角色即时生效、无回弹、无灰全表。

## 架构级冗余（建议排期，非本次卡顿主因）
- **[MEDIUM] 持久外壳被每页各自渲染 → 每次路由切换整块 chrome 重挂载**
  `app/(protected)/layout.tsx` 只包了 `AuthGuard`，而 8 个页面各自 `return <AppShell>…</AppShell>`。
  App Router 下页面组件随路由卸载/重挂，其内部的 TopBar/LeftRail/Aside/Footer 也随之重建 →
  跨页导航时外壳"闪一下 / 重新布局"。
  - 建议：把 `AppShell` 上提到 `(protected)/layout.tsx` 常驻；各页通过一个轻量 context / zustand
    "chrome store"（topbar 的 workspace/project/role、rail.current、hideAside）声明本屏外壳配置。
    收益：外壳不再重挂、WS 不因换页反复连断、观感更稳。属结构性改动，需回归 e2e，建议单独一轮做。
- **[LOW] `useUpdateProjectMemberRole` 与旧的 workspace 角色更新同构**（`features/project/hooks.ts`）
  目前项目成员页无内联角色下拉，暂不触发；若将来加，需同样上乐观更新，避免复刻同一卡顿。
- **[LOW] Issue 列表 `staleTime: 0`**（`features/task/hooks.ts`）：每次进入项目页都 refetch 列表。
  本地无妨，但配合外壳上提后可考虑给个短 staleTime 减少重复拉取。
