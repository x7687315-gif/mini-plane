# 事故：用户登不进自己的软件（2026-10-03）

> 影响：桌面单机版。用户的账户是「北归」，但登录页给他显示的是 `engineer`（我建的演示账户），
> 导致他**登不进去自己的软件**，也看不到刚导入的真实数据。
> 根因全在我：数据归属错了 + 登录页认错了"谁是我"。

---

## 一、发生了什么

用户在他的桌面上打开 Mini Plane，登录页显示的是一个他不认识的账户（`engineer`），
点进去也不是他的账户；他自己的「北归」账户进不去。

## 二、根因链（三层叠加，每层都错在我）

### ① 数据导错了账户（最根本）

`scripts/import_progress.py` 当时默认**建一个叫 `engineer` 的演示账户**并把数据挂在它名下。
更严重的是我把它跑在了**桌面单机版的真实数据库**（`config.settings.desktop`）上——
也就是用户真正在用的那个库。

### ② 登录记忆被写成了别人

为了给导入效果截图，`capture-imported.mjs` 用 `engineer` 免密登录了一次。
登录成功会写 `mp-last-user` 到 localStorage——**而桌面版的 localStorage 在 WebView2 的
profile 目录里，那是用户自己的浏览器存储**。于是他的登录页记住了 `engineer`。

### ③ 登录页把"最后用过的账户"当成了"已经登录的账户"

这是产品设计上的错，不是数据错：

- `mp-last-user` 记录的是"**最后一次用过**的账户"——会随换账户、换身份、脚本登录而变；
- 而用户要的是"**已经登录的账号**"——那是**会话事实**（HttpOnly cookie），应该问 `/auth/me/`；
- 再加上 `desktop/launcher.py` **固定打开 `/login`**，即使会话还有效也先给一张登录页。

三者叠加的结果：明明还登录着，却每次都看到一张写着别人名字的登录页。

## 三、修复

### 数据层

| 动作 | 结果 |
|------|------|
| 删除演示账户 `engineer`（级联其工作区/项目/任务/阶段/日志/Agent Token） | ✅ |
| 删除 `amiya` 名下第一次导入留下的重复工作区 | ✅ |
| 删除「阿米娅」工作区里的重复 MP 项目 | ✅ |
| 以 `DEMO_USER=北归` 重新导入 | ✅ 数据在**北归 → 专用工作区「Mini Plane 开发」→ MP**（16 任务 / 5 阶段 / 2 日志 / 1 运行中 Agent 会话） |

他的原工作区「阿米娅」**未被触碰**。

### 脚本层（防止再犯）

- `import_progress.py` **默认不再创建任何账户**：传 `DEMO_USER` 就用它；没传就用
  **本机最近创建的免密真实账户**（跳过 `e2e_` / `smoke_` 这类自动账户）；
  一个都没有才创建演示账户。
- 工作区改为**按用途建专用工作区**（`mini-plane-<用户名>`），不再"复用账户的第一个工作区"
  ——原来的实现会把项目导进用户自己的其它工作区，而他可能有多个。

### 产品层

1. **`desktop/launcher.py` 打开 `/` 而不是 `/login`**：会话有效时 AuthGuard 直接放行进应用；
   只有会话失效才会被送到登录页。
2. **登录页优先显示"当前会话账户"**：接入 `useMe()`，能问出当前用户就显示**他本人**
   （文案「继续使用」），点一下直接进（无需任何请求）；问不到才退回"上次使用的账户"
   （文案「直接进入」），走原来的免密登录路径。

- 数据归属脚本校验：北归（免密）→ 专用工作区 → MP（16/5/2）✅；`engineer` 已删除 ✅；无重复项目 ✅

## 五、教训（写下来才算记住）

1. **往别人的真实数据里写东西之前，先问"这是谁的"**。演示账户、自动账户这类东西
   只能在一次性环境里用，**绝不能落进用户正在用的库**。
2. **"最后用过的账户" ≠ "已经登录的账户"**。前者是客户端记忆（会错），后者是服务端会话事实
   （不会错）。要显示"你已经登录了"，就问会话。
3. **在用户自己的机器上做操作时，任何写进用户 profile / 存储的动作都要假设"用户会看到"**——
   截图脚本的一次登录，就改掉了他下次打开软件看到的页面。
4. 用户的账户名是「北归」。**动手前先查库里有什么，不要凭印象**。
