# 关闭窗口时弹出 3–4 个闪一下就关的窗口 —— 原因与修复

> 2026-10-04 · 用户反馈："关掉窗口时连续弹出三四个弹窗，闪烁然后又关闭，会不会损害电脑？"
> 结论：**不损害电脑**，纯显示问题，且**是我自己引入的 bug**，已修。

---

## 一、先回答担心的事

**不会损害电脑。** 那些窗口是**黑色控制台窗口**（cmd 那种），只是"被系统临时创建出来又立刻关闭"，
不写任何文件、不改任何数据、不占用资源超过一瞬。它唯一的坏处是**难看且让人不安**。

## 二、为什么会闪

关闭窗口时会走"停服退出"这条路，它需要调用 **`taskkill`**（Windows 的命令行工具）：

| 调用 | 次数 | 现象 |
|------|------|------|
| `kill_tree(后端)` | 1 次 | taskkill 是**控制台程序** |
| `kill_tree(前端)` | 1 次 | GUI 进程调用控制台程序时 |
| `hard_exit` 自毁（杀整棵进程树） | 1 次 | Windows 会临时分配一个控制台 → 黑窗口闪现 |

**正好三四个，与你看到的完全一致。**

## 三、为什么只有关闭时才闪

启动后端/前端那几处**早就加了** `CREATE_NO_WINDOW`（不弹控制台），只有**收尾时漏了**——
我加"关窗即退出"这条通路时，照搬了 `kill_tree` 的写法，而那个写法本身就缺这个参数。

## 四、修复

给两处 `taskkill` 调用补上 `creationflags=CREATE_NO_WINDOW`：
- `kill_tree()`（后端、前端各一次）
- `stop_services(hard_exit=True)` 里的自毁调用

已有的 `migrate` 调用本来就有这个参数，未改动。

## 五、验证

`desktop/verify_quit.py` 增加了"窗口是否真的消失"的测量
（WM_CLOSE 是异步投递，**投递了不等于关掉了**，必须实测）：

```
第 1 次：窗口在 +1s 消失 ✓ → {'MiniPlane': 0, '端口': []} ✅
第 2 次：窗口在 +1s 消失 ✓ → {'MiniPlane': 0, '端口': []} ✅
```

门禁：desktop/ ruff check + format 全绿。

## 六、过程中的一个插曲（记录以防再犯）

修完后第一次验证**反而失败**（进程没退），我一度以为改坏了。
看日志发现那次**连"主窗口已关闭"都没记录**——是 WM_CLOSE 异步投递被忽略（偶发），
不是功能回退。补上"窗口是否消失"的测量后，连续两次稳定通过。

**教训**：自动化验证必须先确认**前置条件成立**（窗口真的关了），
否则会把"测试没触发"误判成"功能坏了"。
