## 问题详情

### 一般（已修复）
【P3C-SEC/正确性】唯一约束 + 可空字段的空值语义
【位置】`apps/users/models.py` / `serializers.py`
【说明】邮箱改为"可选"后，若沿用 `unique=True` 且用空串 `""` 表示"未绑定"，多个未绑定账户会**互相撞唯一约束**
（`IntegrityError`）；且 Django `create_user` 内部 `normalize_email(None)` 会把 None 变成 `""`，
测试 `test_register_nickname_only` 直接暴露了该 bug（返回 `''` 而非 `null`）。
【修复】模型 `email = EmailField(unique=True, null=True, blank=True)`（NULL 不撞唯一）；
`RegisterSerializer.create` **不走 `create_user`**，直接建实例确保存 NULL；
迁移 `0002_alter_user_email` 使列可空。

### 一般（已修复，随上一条）
【P3C-STY / 校验完整性】显式声明字段丢失自动 UniqueValidator
【说明】`RegisterSerializer` 显式声明 `email` 字段后，ModelSerializer 不再自动挂 `UniqueValidator`，
重复邮箱绕过校验、在 save() 抛 500。
【修复】显式补 `validators=[UniqueValidator(queryset=User.objects.all())]`，恢复 400 语义。

### 轻微（评估豁免）
【P3C-SEC-003 参数校验】登录"只给昵称"时对不存在账户返回 404 `not_found`、有密码账户返回 401
`password_required`——**区分了账户是否存在**，严格看是用户名枚举面。
【处理】本产品是**本地单机应用**，攻击面即本机用户本人，枚举无意义；且这是"昵称优先新建 / 二级验证"
交互的必要信号。按 P3C"业务特殊性"豁免，已在 `views.login_view` docstring 注明。

【P3C-OPT-004 国际化】组件内硬编码中文（非 i18n key）——与全项目"中文单机软件"设计一致，已知取舍。
