## 1. 日常项目中的大多数用户痛点（★★）

- **登录/账号摩擦**：这正是你这次踩到的——本地软件不该每次开都要登录。已修（持久会话）。延伸：
  离线/多设备时"我在哪台机器、数据是不是最新的"没有交代 → 需要**数据位置可见 + 一键导出/备份**。
- **信息录入太重**：新建任务要填一堆字段，个人用户只想"快速记一笔"。缺 **全局快捷录入 / 命令面板 / 自然语言快速建任务**。
- **找不到"我的事"**：任务散在项目里，缺一个**"我的工作"个人看板**（跨项目指派给我的、我关注的、逾期的）。
- **视图单一**：只有列表/看板；缺 **日历视图、时间线/甘特、里程碑**，规划类工作难铺开。
- **可定制性差**（vscode#519 👍3783 佐证这是普遍诉求）：字号/主题（明/暗）、列宽、显示字段不能按人调。
- **重复性事务**：周报、例会、周期性任务每次手建 → 缺 **模板 + 周期任务（recurring）**。

## 3. 上游 / 下游存在的问题（★★，值得提前防）

- **上游（我们依赖的）**
  - WebView2 运行时依赖：Win10 老机型可能缺，需在启动器里检测并给"装 WebView2"指引（已部分实现）。
  - SQLite 并发写：单机够用，但多进程/未来多端会 `database is locked`；已设 `timeout=20`，仍需注意长事务。
  - Postgres↔SQLite 双栈漂移：模型改动要保证两套迁移都过（CI 已卡 `makemigrations --check`）。
  - 上游 Plane 本身在快速演进，"仿 Plane"会持续落后 → 建议**明确我们的差异化定位**（本地/离线/个人），而非逐条对齐。
- **下游（用我们的人/系统）**
  - 数据可迁移性：本地单机 → 用户换机/重装怎么带走数据？**导出/备份 + 数据目录固定可见**是刚需（见 G）。
  - 无自动更新：exe 版本迭代后老用户拿不到更新 → 需要**版本检查/更新通道**（哪怕只是提示）。
  - 崩溃可诊断：已加 `runtime/launcher.log`，但用户不会主动翻 → 可加"一键打包日志反馈"。
  - 多用户/协作与"单机"定位冲突：现在角色/成员是本地多账户，非真协作；文档要讲清边界，避免误期。
  - 备份即协作：git-pm 思路（任务存 Git 仓库）能同时解决"备份 + 多端同步 + 版本历史"，对本地工具是低成本高杠杆。

## 4. 已知坑 / 注意

- 别把"仿 Plane"变成"什么都有"：本地个人工具的核心是**轻、快、离线、数据在手**。选特色时以这四点为准绳。
- AI 方向（I/J）先做**只读增强**（摘要、建议），再谈写入，避免幻觉污染数据。
