# Mini Plane 产品原则（唯一事实源）

> 本文是产品层级的最高决策记录。任何新功能、API、模型、UI 设计与本文冲突时，**要么改设计，要么先修订本文**。
> 建立：2026-10-24（个人优先重构 Phase 1）。取代 `PRODUCT_REFACTOR_PLAN.md` 的原则部分（该文档转为历史档案）。

## 六条原则

### 1. 个人优先（Personal First）

用户打开软件的核心动作是：看我的工程 → 开工程 → 定目标与阶段 → 推进任务 → 记录今天做了什么。**任何个人路径不得要求理解 Workspace、成员、角色**。协作是按需叠加的能力，不是个人数据存在的前提。

### 2. 本地优先（Local First）

数据在本机（SQLite 默认），服务只绑 127.0.0.1，DEBUG 关闭，零外部依赖可跑（无 Postgres/Redis/Celery worker 也能用）。桌面版双击即用、会话持久、关窗停服。

### 3. 工程状态优先（State of the Work）

系统的首要问题是「这个工程进行到哪了」，答案的优先级：**当前阶段 / NOW / NEXT > 最近实际记录（Worklog）> 计数与百分比**。百分比只是辅助信息。

### 4. Task 是计划，Worklog 是证据

Task 写「打算做什么」，Worklog 写「实际做了什么、结论如何、下一步、是否被卡」。两者不可合并、互不替代。Markdown 日志是原始事实，本系统是结构化索引。

### 5. Agent 受权受限（Bounded Agent）

Agent 通过本地 API + 独立 Token 接入，只能做 scope 白名单内的事（读项目、建/推进任务、写日志、报进度），**绝不拥有**：删除项目、改 owner、管理成员/角色、改 Plan 结构。所有可重试的写动作必须幂等。Agent 上报什么界面就显示什么，UI 不得推测填充。

### 6. 简约实现（Simple over Clever）

每个实体/接口/抽象必须回答「解决什么真实问题」。不加假想未来的通用层（工作流引擎、DAG、多 Workspace 共享、事件总线）。同一业务事实只有一个计算位置、一个权威来源。轻量：单 SQL 聚合、推送只是提醒不是事实源。

## 边界（本轮明确不做）

MCP 包装、AI 自动规划、多人实时编辑、复杂通知中心、甘特图、跨 Workspace 项目共享、多 owner 转移工作流。
