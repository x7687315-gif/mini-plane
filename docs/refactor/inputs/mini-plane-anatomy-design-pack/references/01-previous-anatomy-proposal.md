> 状态：**待用户评审**（本轮零生产代码）。外部评审意见已全文吸收，本文按其检查表逐项作答。
> 本文件取代 `miniplane-sheet-viz.html` 的「最终方案」地位——那版剖面图降级为**候选 B 的基础**。
> 配套原型：`ui-design/miniplane-anatomy-ab.html`（A 爆炸轴测 / B 剖面式，同一真实数据、同一交互集，可切换对比）。

## 0. 概念冻结（先回答「图为什么要这样画」）

- **工作台回答「现在做什么」，解剖图回答「这个工程由什么构成、各构件推进到哪」。** 两者互补，解剖图不进日常工作流、不替换任务列表。
- 解剖图比现有垂直路线图多回答的问题：**①构成**——16 个任务作为「构件」分布在哪些阶段（路线图只显示阶段级聚合）；**②密度**——哪个阶段构件密集/空洞；**③散件**——还有多少任务未归属阶段（现在无法被看见）。
- 铁律（外部评审指出，全盘采纳）：**Task↔Task 依赖在数据模型中不存在**。图上任务相邻=同阶段分组，**绝不画依赖线/箭头**；未来若引入依赖实体，另行设计。

## 2. 两种构图（明显不同，非同一方案换皮）

### 方案 A · 爆炸轴测（Exploded Axonometric）——「把工程拆开给你看」

阶段=水平楼板沿垂直轴**爆炸展开**（等间距），每块板是 2.5D 平行四边形（顶面+前立面，几何精确、线粗分级）；**任务构件块**摆在板上（done=断面填充块 / doing=钴蓝+NOW / todo=空框，多于 4 块折叠为 `＋n`）；投影虚线把各板连到右缘**累计进度标尺**；未归属任务集中在图底**散件托盘**（虚线框）；Worklog 引线批注在图纸右缘；NOW/Agent 顶部仪表标注。
**气质**：主动展示「这是一个可以被拆解、被检视的人造物」——构成感最强，独特性最高。

### 方案 B · 剖面式路线图（Section，v4）——「把工程竖着剖开给你看」

维持剖面语义（楼层自下而上、层高=权重、45° 断面填充=进度、地面线、标高符号），本轮升级三点：**①构件进层**——层内画任务「房间隔断」（按任务数均分，状态着色），路线图第一次能看见层内构成；**②聚焦态**——点击楼层，该层放大展开任务文本行，其余层压薄成 20px 板；**③散件架**——未归属任务在剖面左侧竖条内，与「已归位构件」形成对照。证据格保留底部。
**气质**：秩序感最强，与现有路线区的演进关系最连续（学习成本≈0）。

### 共同交互（刻意少，评审 MAB 边界内）

1. 整体视图 → 2. 点击阶段=**聚焦**（该阶段展开、其余弱化/压薄） → 3. 点击任务构件=**详情浮卡**（sequence/状态/优先级/stage + 「在工程台打开」示意） → 4. 「整体」按钮恢复。多任务=折叠 `＋n`，聚焦才展开。**无拖拽、无 3D 引擎、无时间回放、无新依赖模型。**

## 3. 五维对比

| 维度 | A 爆炸轴测 | B 剖面式 |
|---|---|---|
| 可读性（一眼看懂） | 好——「拆开的机器」人人可感；但 2.5D 需要一次学习 | **最好**——楼层隐喻零学习成本；聚焦后层内可读性更高 |
| 独特性（差异化） | **最高**——同类 PM 无此构图，最像「收藏级图纸」 | 中高——剖面+构件仍属罕见，但视觉与工程台路线区连续 |
| 操作成本 | 聚焦/恢复多一步（爆炸间距大，视线跳跃远） | **最低**——聚焦态就近展开 |
| 实现难度 | 中高——2.5D polygon 数学 + 聚焦态重排动画 | 中——v3 剖面的直接演进 |
| 扩展能力 | 好——新阶段=新板；任务依赖实体若将来出现，可画「板间传送线」 | 好——层内房间可承载更多构件类型；竖向空间受限（阶段多则需滚动） |

**推荐：A 为 PLATE 主视图（差异化的旗），B 的聚焦机制并入 A 的交互，B 本体保留为工程台「路线」区的演进形态。** 理由：用户要的「其他工具不容易提供的体验」主要由 A 承载；而日常高频的轻量推进仍由工作台与 B 负责——互补结构正是外部评审建议的形态。

## 4. MVP 边界

**第一版做**：PLATE 视图（A）进工程台为独立次级视图（工作台/图纸两个 Tab）；聚焦+任务详情浮卡（浮卡内「打开抽屉」接现有 `?issue=` 语义）；散件区；Worklog 批注；NOW/Agent 标注；空态（无阶段/无任务的诚实文案）。
**第一版不做**：编辑（图只读）、拖拽、任务依赖线、3D、时间回放（Gource 式，留待历史模式）、Island 缩略图（第二步）、打印/导出。
**前置数据提示（诚实）**：现有任务的 `stage` 多为空——图上它们会落在散件区，这本身是有用信息（催归属），不做假数据。

## 5. 验收（怎么证明「有助于理解」而非「更漂亮」）

1. 三档数据实测：简单（1 阶段 3 任务）/ 标准（5 阶段 16 任务）/ 密集（5 阶段 50+ 任务）——聚焦态下当前焦点是否突出、图纸秩序是否保持；
2. 任务定位计时：从 PLATE 找到「当前阶段的某个 todo 任务」应 ≤2 次点击；
3. 语义自查：图上不存在任何一条不对应真实字段的线条；
4. 既有 E2E 不回归（PLATE 为新增视图，不动任务列表路径）。
