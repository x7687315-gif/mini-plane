## 0. 我对产品内核的复述

Mini Plane 的用户是**一个人持续推进多个工程**。每天打开软件是为了回答三个问题：

1. **我的工程都到哪了？**（阶段 / NOW / NEXT / 最近证据 / Agent 是否在跑）
2. **现在最值得继续哪一个？**（选择，不是浏览）
3. **做完了记一笔。**（Worklog 是证据，不是任务完成打勾）

团队协作是这三个问题之外的能力：它必须完整存在，但**不参与组织个人首页、主导航与默认路径**。Task=计划、Worklog=证据、Stage=路线、NOW/NEXT=推进焦点、Agent 状态=真实上报——这五个语义是产品身份，UI 重构不能稀释它们。

## 1. 交付一：根本结构问题（按影响排序）

| # | 问题 | 证据（截图可确认的事实） | 受损场景 / 频率 | 建议方向 | 代价 |
|---|---|---|---|---|---|
| **R1** | **首页是「统计+孤岛卡片」，不是决策面板** | My Engineering 首页：1 个工程时 ~90% 画布是空网格；卡片无任何行动按钮（无「进入」「记录」），看完仍要二次导航 | 每天打开的第一屏 · 每次 | 首页改「继续工作区 + 行式工程列表」，行内直挂进入/记录动作 | 卡片视觉弱化，需重排信息密度 |
| **R2** | **工程页是管理控制台，不是工作台** | 项目页首屏被 Stage 编辑（进度输入框/设为当前/加阶段）+ 完整 Worklog 表单占据，TASKS 列表在折叠线以下 | 进入工程的每次 · 最高频 | Stage 默认只读路线；Task 列表为主区；编辑类收进「计划/设置」次级视图或编辑态 | 阶段编辑多一层进入动作 |

| **R7** | **「今日日志」统计与记录入口错位** | 首页有「今日日志 0」统计，但记录入口在项目页底 | 记录 · 每天 | 快速记录入口进首页行内动作（R1）与命令面板 | 无 |
| **R8** | **Stage 进度裸数字编辑违背「百分比是辅助」** | 每行 stage 有裸进度输入框 + 「设为当前」按钮常驻 | 调整计划 · 低频 | 路线只读呈现（进度条+当前标记）；编辑进「计划」编辑态 | 无 |

## 2. 交付二：关键流程对照（现状 → 建议）

操作数=主要点击/按键；概念数=用户需理解的产品概念。

| 流程 | 现状 | 建议 | 变化 |
|---|---|---|---|
| 1. 打开 → 找到要继续的工程 | 首页读统计 → 读卡片 → 点卡片标题进项目页（**2 次跳转，无行动提示**） | 首页「继续」区直接显示 NOW 任务行，点击即开任务抽屉；或点工程行进入（**1 次点击**） | 2→1，且首屏即答案 |
| 2. 创建个人工程 | 首页空态引导「去创建工作区」→ 工作区列表 → 建工作区 → 项目列表 → 新建项目（**4 步 + 2 概念**） | 首页/命令面板「新建工程」→ 表单（名称/标识符）→ 创建即进入（**1 步 + 0 概念**；后端 Phase 3 已支持 `POST /api/v1/projects/` 默认私人） | 4→1 |
| 3. 进工程 → 推进 NOW | 进项目页 → 滚过 Plan/Log → 找 TASKS → 找行 → 点开抽屉（**≥2 次滚动 + 1 跳转**） | 工程台首屏即 Task 主区，NOW 行置顶高亮（**0 滚动**） | 滚动消除 |
| 4. 完成工作 → 记 Worklog | 项目页 → 滚到底 → 6 字段表单（**滚动 + 多字段**） | 任意页面 ⌘/Ctrl+L 或行内「记一笔」→ 2 字段弹层 → 提交（**0 滚动 + 2 字段**） | 成本最大降幅 |
| 5. 调整 Stage 计划 | 项目页直接改（常驻控件） | 工程台「计划」视图 → 编辑态（多 1 次进入，低频合理） | +1 点击，换常驻降噪 |
| 6. 查任务详情/评论 | 抽屉（已较好） | 保留抽屉；重排字段层级（R6） | 结构不变 |
| 7. 需要协作时 | 顶栏 ⇄ 或左栏工作区 | 左栏「团队协作」区（有团队数据才出现）→ 工作区页保留完整管理；返回个人=点 logo/我的工程 | 入口收敛，能力不减 |

## 3. 交付三：两种信息架构

### 方案 A · 工程总览 + 工程工作台（推荐）

```text
左栏（个人层）            首页 /                    工程台 /projects/{pid}
├ 我的工程（默认）        ┌ 继续工作（NOW×N 行）     ┌ 状态头：阶段·进度·NOW·NEXT·Agent
├ 我的工作                ├ 工程列表（行式）          ├ TASKS 主区（筛选合一）
├ Island                 │   每行：名·阶段·进度      ├ Tabs：计划 | 日志 | 设置
└ 我的设置               │      ·NOW·NEXT·Agent     └ （计划=只读路线+编辑态）
（有团队数据时）          │      ·行内[进入][记一笔]
├ ── 团队协作 ──          └ [+ 新建工程]
├ 工作区与工程
└ 成员与设置
```

- **首页回答「选哪个」**：继续工作区把跨工程的 NOW 汇成 3~5 行可点击行（数据已在 `/projects/mine/` 聚合里，**零新 API**）；
- **工程台回答「做什么」**：Task 列表是一号位，计划/日志按需切换；
- 1 个工程时首页依然是完整决策面板（统计条并入「继续」区头部，不再有孤岛卡片）。

### 方案 B · 今日工作流优先

```text
首页 = 「今天」：跨工程 NOW 聚合 / 待补日志提醒 / 最近证据流；工程列表降为次级入口
```

- 更激进的「收件箱化」；多工程并行时决策最快；
- **代价**：需要新聚合端点（跨工程 NOW 排序）；「今日」视图在工程少时内容稀薄；与 Island/Plan 的工程中心语义有张力；「待补日志提醒」有凭空推断用户行为的违规风险（原则 §5：不凭空推断）。

### 取舍结论

**主推 A，吸收 B 的一个元素**（首页顶部「继续」区=今日视角），理由：
1. 零新 API 依赖（B 需要新聚合端点，违背本轮「不动后端」约束）；
2. 工程为单位的心智模型与 Plan/Worklog/Island 一致，学习成本为零；
3. 1→10 个工程线性可扩展（B 在 0~1 个工程时开天窗）。

```text

│                            │   │ │ 完成了什么 [__________]  │    │
│                            │   │ │ ▸ 补全：结论/下一步/阻塞  │    │
│                            │   │ │          [记录] (Enter)  │    │
│                            │   │ └──────────────────────────┘    │
└────────────────────────────┘   └─────────────────────────────────┘
```

- 默认 2 字段 + 日期默认今天 + 阶段默认当前阶段（可改）；「补全」展开完整字段——**同一 Worklog 实体、同一端点**，不存在两套数据流；未提交输入驻留内存直至提交或显式取消。

## 5. 交付五：推荐方案与明确取舍

**推荐方案 A（工程总览 + 工程工作台），首页吸收「继续」区。**

- **第一眼看到什么**：「继续」区——跨工程 NOW 的前 3~5 行，每行可直接开始/记录。它直接回答「现在做什么」，而不是「我有什么」。
- **留在首屏**：继续区、工程行列表、新建工程。**进入按需区**：计划编辑、完整日志表单、设置、协作管理、批量操作（保留在 Task 主区工具条，行为不变）。
- **个人工程创建/进入/继续**：首页与命令面板直达创建（`POST /api/v1/projects/` 已就绪）；进入=点行；继续=点 NOW 行（开抽屉）。
- **团队位置**：左栏折叠区 + 保留完整工作区页——能力零删减，注意力降权。
- **保留的旧规则**：Blueprint 视觉体系全量保留（纸面/衬线/钴蓝/0.5px 线）；URL 即筛选/抽屉状态；动态倒序+评论正序；乐观更新；诚实占位（不推断停滞/阻塞）；JetBrains Mono 仪表数据层。
- **修改的旧规则**：装饰坐标/微标签在正文区降密度（保留页缘）；「一屏读完」让位于「一屏可行动」；网格底纹在列表/表单区减弱。
- **风险与代价**：
  1. 计划编辑 +1 层进入（低频换降噪，可接受）；
  2. 「继续」区依赖 NOW/NEXT 的启发式排序（现状 SQL 已定义，语义冻结在 DOMAIN_MODEL §3，不新增推断）；
  3. 新路由 `/projects/{pid}` 与旧 `/w/{slug}/projects/{pid}` 并存期的一致性维护（TD-08）；
  4. 左栏团队区对纯团队用户多一次展开动作（此类用户非本轮主用户）。

## 7. 交付七：最小验证原型与分期计划

**为什么先验证这两个场景**：首页决策（R1/R7）与工程台推进（R2/R3）覆盖了五个根本问题里的四个，且都是每天多次的高频路径——它们若不成立，其余重排无意义。

| 阶段 | 范围 | 验证方法 | 验收标准 | 依赖/回滚 |
|---|---|---|---|---|
| **1. 原型验证**（本轮） | HTML 低保真：首页 A/B + 工程台 A/B + 快速记录弹层 | 用户评审 + 真实数据代入（1/3/8 工程三档） | 用户确认方案 A 与取舍 | 纯静态 HTML，零回滚 |
| **2. 核心工程台** | `/projects/[pid]` 路由 + 状态头 + TASK 主区 + Tabs | 现有 E2E 子集（issue-thread）改走新路由 | 进工程 0 滚动见 NOW；筛选/URL 语义不回归 | mine 聚合 `now_task` 扩对象（唯一后端改动）；旧路由重定向保底 |
| **3. 首页与导航** | 首页继续区/工程行 + 左栏团队区 + 空态 | E2E：新建个人工程 ≤2 步断言 | 指令 §九 全指标过（2→1、4→1 等） | 首页可整页回退 |

| **5. Drawer 与一致性修整** | Drawer 重排 + Island 数据适配核对（不改窗口壳） | 既有 island/realtime E2E | R6 消除；Island 显示数据不变 | Drawer 内部重排，外部接口不变 |

**每阶段收尾**：devlog + 截图对比 + CI 全绿；顺序可在评审后调整，但 1→2 的「先验证高频场景」不变。

## 8. 对结尾五问的直接回答

1. **首页应该是什么**：一张「接下来做什么」的决策面板——继续区（跨工程 NOW）+ 可行动的工程行列表。**不应该是什么**：统计摘要 + 需要二次导航的孤岛卡片，或 workspace 仪表盘。
2. **每天最高频的 3 个动作**：①看进度选工程（继续区）②推进 NOW 任务（工程台主区+抽屉）③记一笔 Worklog（全局快速记录）。三者都应 ≤1 次点击到达。
3. **团队能力放哪**：左栏「团队协作」折叠区（有团队数据才出现）+ 保留完整的 /w/{slug} 管理页——能力零删减、入口降一级、不与个人路径共享任何必经步骤。
4. **最能验证重构的小原型**：首页「继续」区 + 工程台首屏（本原型已含）——它同时检验 R1/R2/R7 三个最高频问题。
5. **保留 vs 修改**：保留蓝图视觉体系、URL 即状态、双序时间线、诚实占位；修改「一屏读完」教条、常驻编辑表单、对称双入口、裸数字进度编辑、装饰密度。
