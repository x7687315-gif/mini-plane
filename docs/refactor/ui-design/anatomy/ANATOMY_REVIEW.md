# 解剖图三方案三维审查 + 组合性分析（Round 1）

> 依据用户三维标准：①UI 设计（对照主流高收藏设计）②项目匹配度（功能覆盖）③实操与构成宗旨（简明扼要）；另加用户点名的**组合性**考察。
> 结论先行：**最优解是组合而非单选——A 爆炸轴测为主体 + B 剖切聚焦为交互态 + C 的版式面板为信息层**，合成一张复合 PLATE 视图。这正是概念方向图本身的构成（爆炸构件 + 右侧索引面板 + 图例 + 图签），组合性已被该图验证。

## 一、三维评分（10 分制）

### ① UI 设计（对照主流高收藏设计）

参照系：GitHub Skyline / Isometric Contributions（4.9★）的等距楼栋隐喻、Excalidraw 手绘思考工具、OpenProject 甘特、CodeCharta 代码城市、以及编辑式版面（Divisare 类图纸排版）。

| 方案 | 评分 | 判断 |
|---|---|---|
| A 空间爆炸图 | **9.0** | 与等距「城市/楼栋」主流语言同构（Skyline 系被数百万人接纳的认知）；五阶段五种建筑原型带来收藏级图纸的独特性 |
| B 轴测剖切图 | 7.0 | 剖切内景在建筑图纸常见，但作为独立视图语义单一；「一次只深读一层」与主流 PM 的多阶段总览预期不符 |
| C 工程图纸版式 | 8.0 | 编辑式版面+索引表是设计成熟度最高的（信息层级专业）；但主图缩小后空间感被面板稀释 |

### ② 项目匹配度（功能覆盖）

覆盖清单：Stage order/weight/progress/is_current/goal · Task 状态/优先级/stage 归属（含**散件**）· Worklog 证据关联 · NOW/NEXT · Agent 运行态 · 总进度+progress_source。

| 方案 | 评分 | 覆盖情况 |
|---|---|---|
| A | 8.5 | 全部可承载（层=order、层高=weight、填充=progress、细胞=Task+状态色、散件托盘、NOW 旗标、Agent 角标）；Worklog 批注与 goal 显示待补（原型已预留） |
| B | 7.0 | 单阶段内部最佳（构件阵列+状态统计），但**整体构成被幽灵化**——Stage 间对比、散件、总览全弱化 |
| C | **9.0** | 覆盖最全：主图+索引表（每阶段任务数/百分比/散件计数/进度来源）+DETAIL 模块——唯一能把「精确数字」与「空间结构」同时呈现的方案 |

### ③ 实操与构成宗旨（简明扼要，快速理解梳理）

| 方案 | 评分 | 判断 |
|---|---|---|
| A | 8.0 | 「盖到第几层、哪里最密」一眼可读；2.5D 需一次性学习；标签密度需控制（已按规格 §4.4 收敛） |
| B | 7.5 | 单阶段阅读最快，但整体往返成本高 |
| C | **9.0** | 索引表+主图双通道，找信息最快；纯空间感稍弱于 A |

## 二、组合性分析（用户点名的关键考察）

| 组合 | 评估 | 结论 |
|---|---|---|
| A 单独 | 主图强、精确信息弱（只有色块与百分比，没有索引数字） | 不完整 |
| B 单独 | 语义过窄 | 淘汰作为独立视图 |
| C 单独 | 信息全但空间感被面板稀释 | 不完整 |
| **A + C** | 概念方向图自身的构成：爆炸构件为主图，右侧索引/摘要面板、图例、图签为信息层——**已被该图验证成立** | ✅ 静态层最优 |
| A + B | A 全景 + 点击剖切聚焦（其余幽灵化）——互补且交互自然 | ✅ 交互层最优 |
| **A + B + C（复合 PLATE）** | 全景(A) + 点击阶段剖切聚焦(B) + 常驻索引/图例/摘要面板(C)；任务点击→现有抽屉 | ✅✅ **最终方案**：单一视图同时回答「构成/密度/散件/当前焦点/精确数字」五类问题，且零新操作 |

组合后的阅读动线（与外部评审 §5.1 的注意力顺序一致）：主体轮廓 → 当前/聚焦阶段 → 任务分布与散件 → 索引数字 → 图纸元信息。

## 三、评分汇总与决定

| 方案 | UI | 匹配 | 实操 | 组合后加权 | 
|---|---|---|---|---|
| A 单独 | 9.0 | 8.5 | 8.0 | 8.5 |
| B 单独 | 7.0 | 7.0 | 7.5 | 7.2 |
| C 单独 | 8.0 | 9.0 | 9.0 | 8.7 |
| **A+B+C 复合 PLATE** | 9.0 | **9.5** | **9.0** | **9.2 ← 采纳** |

**决定：实施复合 PLATE 视图**——A 的空间爆炸主体（每阶段独立建筑原型）+ B 的剖切聚焦交互（点击阶段，其余幽灵化）+ C 的常驻信息面板（阶段索引/图例/摘要/图签）。任务点击接现有 `?issue=` 抽屉；视图只读；零后端改动。

## 四、本轮实施范围（后续轮次）

- **Round 2**：`AnatomyPlate` 组件（等距引擎 + 三方案合成 + 空态/高密度/响应式），独立于路由先做组件级验证。
- **Round 3**：接入工程台（`?view=plate` 视图切换），浏览器实测真实数据（简单/标准/密集三档），修复问题。
- **Round 4**：实施报告 + 推送；用户全局安全检查与手动审查。
