# Anatomy V3 · Phase 2 高保真原型记录

> 日期：2026-10-28 · 分支 `feat/anatomy-v3`
> **生产接入已完成（2026-10-29），结果见 [`PHASE3_REPORT.md`](PHASE3_REPORT.md)。**
> 产物：[`prototype.html`](prototype.html)（独立 HTML + SVG，不接生产路由、不改 API/数据库）
> 依据：[Phase 1 审计](PHASE1_AUDIT.md) · [技术 Preflight](PREFLIGHT.md) · 用户草图与文字规划

## 1. 原型包含什么

- **生长视图**：Stage 从旧到新垂直累积；当前 Stage 顶面/索引高亮；
  Stage 的前缘用真实任务密度的短竖线表示（已完成/进行中/待处理/已取消），
  不把 Task 猜成依赖关系；本轮按反馈整体放大约 30%（`w=380,d=220,step=112`），
  画布超过视口时用 `.canvas-scroll` 提供纵向滑轨；
- **结构视图**：左侧保留完整的 **Project whole ghost stack**（5 个半透明 Stage 层
  叠成整体），右侧把 5 个 Stage 模块水平爆炸展开；每个模块用虚线回连到它在整体中
  的原始层位（`DASHED · ORIGINAL POSITION`），形成“整体 → 拆出局部”的读法。
  虚线只表示原位，不表示任务依赖；
- **固定详情区**：选中 Stage 的目标、记录进度、权重、任务总数/完成/进行中、
  任务清单和演示记录；进度使用 Stage 自身记录值，不用任务完成率反算；
- **索引**：保留真实 Stage 顺序、进度、任务数，点击与 SVG 同步选中；
- **未归属任务**：独立的虚线托盘，可见、中性，不塞进任何 Stage；
- **视图切换**：生长/结构共享同一数据和当前选中 Stage；
- **响应式**：桌面三栏（索引 / 主图 / 详情）；移动端单栏，结构图允许横向滚动，
  生长图隐藏长标签但保留序号与索引/详情；
- **可访问性**：Stage 构件 `role=button`、`tabIndex=0`、Enter/Space、可见焦点环；
  尊重 `prefers-reduced-motion`；
- **安全**：演示文本经 `esc()` 转义后进入 SVG；无 `dangerouslySetInnerHTML` 等价物。

## 2. 设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 技术 | React/SVG 的等距投影思路，原型用原生 HTML+SVG | 不引 3D 引擎；坐标、线宽、测试可控 |
| 成长方向 | 旧 Stage 在下、新 Stage 在上 | 像建筑施工逐层加高；**不伪造 DAY 01→03** |
| 结构方向 | 水平分离 + 少量垂直错位 | 表达阶段组成，同时保留整体轮廓 |
| 整体与局部 | 左侧 ghost 整体堆叠 + 右侧爆炸模块 + 虚线回连原位 | 直接回答“局部从整体哪里拆出来”，避免读成一排卡片 |
| 生长视图尺寸 | 相对上一版放大约 30%，配纵向滚动 | 满足“看得更大”；内容超过视口时可上下滑动 |
| Task 表达 | 生长视图前缘密度线；结构视图顶面小立方体 | 层叠时任务不被上层楼板完全遮住；精确信息放详情 |
| 选中 | 顶面轮廓加粗 + 索引高亮 + 详情固定 | 不只靠颜色；切换视图不丢选中 |
| 移动端 | 单栏；结构图横向滚动并显示“横向滑动查看全部构件”，生长图隐藏长标签 | 手机优先保证可读性，而不是强行塞进一屏 |
| 历史 | 不生成按日回放 | Worklog/Activity 不是完整快照；没有快照就不假装有 |

## 4. 与示意图的差异

1. 示意图里的 `DAY 01 → 03` 没有直接照搬：现有数据只有 Stage，没有可靠的按日快照；
   原型改成 `STAGE 01 → 05`，并在文案里明确“不伪造历史”。
2. 生长视图把 Task 放在构件前缘，而不是顶面；因为多层堆叠时顶面会被上层遮挡。
   结构视图仍把 Task 放回顶面，保留“构件内部工作单元”的空间感。
3. 结构视图不再用“共同基座/包络线”，改为按反馈做成 ghost 整体 + 爆炸模块 +
   虚线原位投影；这些虚线是空间位置提示，不是新的数据关系。
4. 详情区固定为右栏；移动端下移，不把主图挤成一条。

## 5. 用户确认结果（2026-10-28）

1. **生长视图尺寸**：选择 **“大图 + 滑轨”**。保留当前约 30% 放大，不为了塞进一屏而缩小；
   内容超过视口时用纵向滚动查看。
2. **手机结构图**：目标改为 **纵向滚动**，不做横向拖动画布；本轮暂缓，
   等桌面版稳定后再实现。当前手机横向滚动只是原型阶段的临时方案。
3. **结构视图方向**：用户未再对“左侧 ghost 整体 + 右侧爆炸模块 + 虚线回连原位”
   提出修改，按该方向进入桌面生产接入；如后续观看真实数据后需要调整，再回改。
4. **其余细节**（Task 表达、详情密度）不阻塞生产接入，可在真实数据上继续微调。

仍待生产版验证的问题：

- 生长视图的“新旧方向”在真实数据下是否仍然直觉（旧下新上）；
- 大量 Stage/Task 时，索引、详情和画布的滚动边界是否稳定；
- 生产版本需要把“当前已加载记录”与“完整历史”继续分开表述。

确认后再进入 Phase 3：把样稿拆成 `layoutGrowth` / `layoutStructure` 纯函数、扩展 `state.ts` 的视图维度，并接生产数据。

## 6. 生产接入前必须解决的问题

- 当前工程台只向 Anatomy 传 `per_page=100` 的第一页 Task；>100 Task 会漏构件、
  任务计数和 NOW 归属可能错误。生产接入前需要全量 Task 或专用轻量端点。
- Activity / Worklog 记录区同样是分页数据；要么明确“当前已加载”，要么做显式分页/全量。
- 原型没有接任务详情抽屉、真实 NOW/NEXT/Agent 数据；这些在 Phase 4/5 接。
